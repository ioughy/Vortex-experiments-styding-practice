# Vortex Experiments: Strong Scaling Study

Репозиторий содержит скрипты автоматизации для параметрического анализа открытой GPGPU-архитектуры **Vortex** на задаче `sgemm` (умножение матриц одинарной точности, OpenCL).

Эксперименты проводятся в симуляторе `simx`, входящем в состав Vortex. Варьируются количество вычислительных ядер и размер входных матриц. Из логов извлекаются метрики производительности, после чего строятся графики сильного масштабирования.

---

## Аннотация

Цель работы — исследование масштабируемости и узких мест иерархии памяти GPGPU-архитектуры Vortex.  
В рамках экспериментов проверяются следующие исследовательские вопросы:

- **RQ1:** влияет ли увеличение количества входных данных на масштабируемость задачи `sgemm`?
- **RQ2:** является ли масштабирование задачи `sgemm` линейным?

Репозиторий позволяет воспроизводимо запускать серию экспериментов, сохраняя логи `simx`, извлекать метрики из них и визуализировать результаты.

---

## Возможности

- Автоматическая сборка конфигураций Vortex под разное число ядер.
- Запуск задачи `sgemm` для размеров матриц `64`, `128`, `256`, `512`.
- Парсинг логов `simx` и извлечение метрик:
  - количество тактов (`cycles`);
  - ускорение относительно одного ядра (`speedup`);
  - другие метрики, доступные при `perf=1`.
- Построение графиков сильного масштабирования с линией линейного ускорения.
- Сохранение результатов в `CSV` и `PDF`.
- CI с использованием Ruff и ShellCheck (GitHub Actions).

## Требования

Проверенная среда:

- **ОС:** Ubuntu 24.04.4
- **Процессор:** Intel Core Ultra 5 125H / x86_64
- **ОЗУ:** 16 ГБ LPDDR5X
- **Vortex:** коммит `9540c33`
- **Python:** 3.14.4
- **pandas:** 3.0.2
- **matplotlib:** 3.10.9
- **uv:** пакетный менеджер (используется для управления зависимостями)
- **Bash:** стандартная оболочка UNIX-подобных систем

Также требуются:

- Git;
- инструменты сборки Vortex: CMake, Make, компилятор C++;
- зависимости Vortex и `simx`;
- OpenCL-стек, используемый проектом Vortex.

> Для конфигурации с 64 ядрами требуется патч `sim/simx/mem/cache.h`:  
> поле `num_inputs` в структуре `Cache::Config` нужно расширить с `uint8_t` до `uint16_t`,  
> так как при 64 ядрах значение `VX_CFG_L3_NUM_REQS` достигает 256.

## Быстрый старт

```bash
git clone https://github.com/ioughy/Vortex-experiments-styding-practice.git
cd Vortex-experiments-styding-practice

# Установка зависимостей через uv
uv sync
```

Укажите путь к локальной копии Vortex:

```bash
export VORTEX_HOME=/path/to/vortex
export VORTEX_COMMIT=9540c33
```

Запустите полный пайплайн:

```bash
./scripts/run_all_experiments.sh
```

## Параметры экспериментов

| Параметр | Значения |
|---|---|
| Приложение | `sgemm` |
| Размеры матриц `N` | `64`, `128`, `256`, `512` |
| Количество ядер | `1`, `2`, `4`, `8`, `16`, `32`, `64` |
| Флаг производительности | `perf=1` |
| Размер блока | `32 × 32` потоков |
| Потоков на ядро | `1024` |
| Число блоков | `N² / 1024` |

Используемая конфигурация Vortex:

```text
VX_CFG_NUM_THREADS = 32
VX_CFG_NUM_WARPS = 32
VX_CFG_L2_ENABLE = true
VX_CFG_L3_ENABLE = true
VX_CFG_L2_SIZE = 4194304
VX_CFG_L3_SIZE = 8388608
VX_CFG_DCACHE_SIZE = 131072
VX_CFG_DCACHE_NUM_WAYS = 16
VX_CFG_PLATFORM_MEMORY_NUM_BANKS = 16
```

## Формат метрик

Ускорение рассчитывается как:

```text
speedup = cycles_1 / cycles_N
```

где `cycles_1` — время выполнения на одном ядре, `cycles_N` — время выполнения на `N` ядрах.

## Результаты

В ходе экспериментов были получены графики сильного масштабирования для задачи `sgemm`:

- `strong_sgemm_64.pdf` — матрица `64 × 64`;
- `strong_sgemm_128.pdf` — матрица `128 × 128`;
- `strong_sgemm_256.pdf` — матрица `256 × 256`;
- `strong_sgemm_512.pdf` — матрица `512 × 512`.

Основные наблюдения:

- при `N = 64` доступно всего 4 блока, поэтому эффективно загружаются не более 4 ядер;
- при `N = 128` доступно 16 блоков, поэтому масштабирование останавливается на 16 ядрах;
- при `N = 256` блоков хватает на 64 ядра, но при 64 ядрах появляется конкуренция за память;
- при `N = 512` достигается ускорение около `63.0×` на 64 ядрах.

## Воспроизводимость

Симулятор `simx` является детерминированным, поэтому результаты запусков воспроизводимы без статистического разброса.  
Для воспроизведения экспериментов важно использовать:

- указанный коммит Vortex;
- ту же конфигурацию ядра;
- те же размеры задач и количество ядер;
- те же версии Python-библиотек (фиксируются в `uv.lock`).
